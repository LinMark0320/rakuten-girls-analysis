# 0002. 爬蟲執行排程策略與前端雙軌互動設計

## Context
在確定混合式資料獲取與 SQLite 儲存後，需要進一步決定爬蟲的執行週期、2023–2026 三年歷史數據的補足手段，以及前端使用者如何檢索這批大量數據。

## Decision
1. **執行週期**：採用「背景定時排程 + 按需手動一鍵觸發」雙軌制（`run_scanner.py` 可由 Windows Task 排程自動執行，亦可在前端或 CLI 隨時點擊觸發最新爬取）。
2. **歷史深度策略**：採用「初始歷史種子庫（Seed Data）+ 增量沉澱」模式。先匯入 2023–2025 年已驗證之主要成員重大成交紀錄，並即時自動爬取當前所有線上競標與近 90 天結標資料，持續累積擴增。
3. **前端檢索介面**：在 `index.html` 同時提供「全局多維度即時檢索過濾面板」與「27 位隊員卡片點擊穿透彈窗（Modal Drill-down）」，並附帶「FB 貼文快貼解析器（Paste & Parse）」。

## Consequences
- **優點**：兼顧平日數據自動累積與臨時急需查價的即時性；前端既能全局橫向比較全聯盟最高價，又能縱向穿透單一成員歷史。
- **取捨**：前端需支援非同步載入 `cards_data.json`，並在本地檔案模式（`file:///`）下具備內建備用資料集（Fallback Dataset）以確保離線直接可用。
